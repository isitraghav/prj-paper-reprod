# Jobs for the RTX 4070 laptop (8 GB): P1 training

This machine trains **P1 (GBH-YOLOv5 paper)**: the YOLOv5s baseline and GBH-YOLOv5, 500 epochs each at 960 px.
P2 is already trained on Laptop B. Background: `init.md` (§3 settings, §11 deviations), `CHECKLIST.md` (§4 parameter table).

Work through the steps **in order** and tick them off. Paste every result line into `init.md` §13 (Progress log).
Commands are for **Git Bash** on Windows (on Linux use `envs/p1/bin/python` instead of `envs/p1/Scripts/python.exe`).

## What must match the paper (do not change)
| Setting | Value | Where it comes from |
|---|---|---|
| Code | CCNUZFW/GBH-YOLOv5 @ `51ee042` + whitespace fix patch | step 2 |
| Model GBH | authors' released `yolov5s_pv.yaml` → `code/repro/p1/gbh_released.yaml` (user decision) | committed |
| Model baseline | ultralytics v5.0 `yolov5s.yaml`, nc 5 → `code/repro/p1/yolov5s.yaml` | committed |
| Optimizer / LR | Adam (`--adam`), lr0 0.001 (`code/repro/p1/hyp.gbh.yaml`) | `run_p1.sh` |
| Epochs / image size | 500 / 960 × 960 | `run_p1.sh` |
| Init weights | COCO `yolov5s.pt` from the yolov5 **v5.0** release (SHA256 in `weights/SHA256SUMS`) | step 2 |
| Data | PV-Multi-Defect @ `2c4df0c`, **frozen** split 886 / 222 (`datasets/splits/pv_multi_defect`) | step 3 |
| Env | Python 3.8.20, torch 1.8.1+cu111 (locked in `code/repro/env/p1/uv.lock`) | step 1 |
| Batch | paper 16. Use **16 if it fits** (expected for YOLOv5s), otherwise the largest **divisor of 64** that fits (expected GBH 8). Accumulation keeps 64 images per optimizer step either way. | step 4 |

Never re-split the data, never edit the yamls/hyp, never tune on the val set. Anything else that has to change → write it in `init.md` §11 first.

## Known pitfalls (from Laptop B)
- `UV_PROJECT_ENVIRONMENT` must be an **absolute** path, otherwise the env lands inside `code/repro/env/p1/`.
- The Windows driver spills VRAM into system RAM instead of OOM: judge batch fit by speed and the probe, not by errors.
- Each dataloader worker on Windows reserves ~3.5 GB of commit, the trainer ~10 GB: too many workers → misleading CUDA OOM.
- Never run two trainings (or a training plus an eval) on the GPU at the same time.
- Warm-up: GBH's code warms up for max(3 epochs, 1000 iters): ~18 epochs at batch 16, ~9 at batch 8. Not changed; note it in §11.
